# 架构决策记录（ADR）标准

## 1. ADR 定义

ADR（Architecture Decision Record）是记录架构决策的轻量级文档，用于：
- 记录为什么做出某个架构决策
- 记录决策的上下文和约束条件
- 记录决策的后果和权衡
- 为未来的架构演进提供历史依据

## 2. ADR 结构

### 2.1 标准模板
```markdown
# ADR-[编号]: [决策标题]

## 状态
[提议中 | 已接受 | 已废弃 | 已替代]

## 上下文
[描述需要做出决策的背景、问题和约束条件]

## 决策
[描述做出的决策内容]

## 后果
[描述决策带来的影响，包括正面和负面]

## 替代方案
[描述考虑过但未采纳的其他方案及原因]

## 相关决策
[列出相关的 ADR 编号]

---
- 日期：2025-01-15
- 决策者：张三、李四
- 审阅者：王五
```

### 2.2 字段说明

**状态**：
- 提议中（Proposed）：正在讨论中
- 已接受（Accepted）：已通过评审并实施
- 已废弃（Deprecated）：不再推荐使用
- 已替代（Superseded）：被新的 ADR 替代

**上下文**：
- 业务背景和技术背景
- 需要解决的问题
- 约束条件（时间、成本、技术栈）
- 质量属性要求（性能、可用性、安全性）

**决策**：
- 清晰描述决策内容
- 说明决策的关键要素
- 必要时附带架构图

**后果**：
- 正面影响（优势、收益）
- 负面影响（风险、成本、技术债）
- 对团队、系统、用户的影响

**替代方案**：
- 列出至少 2-3 个替代方案
- 说明为什么未采纳这些方案
- 对比分析（表格形式）

## 3. ADR 命名与编号

### 3.1 文件命名
- 格式：`ADR-[编号]-[短标题].md`
- 编号：4 位数字，从 0001 开始递增
- 短标题：kebab-case，简洁描述决策主题
- 示例：`ADR-0001-use-postgresql-as-primary-database.md`

### 3.2 存储位置
```
docs/architecture/adr/
├── ADR-0001-use-postgresql-as-primary-database.md
├── ADR-0002-adopt-microservices-architecture.md
├── ADR-0003-use-redis-for-caching.md
└── README.md  # ADR 索引
```

## 4. ADR 生命周期

### 4.1 创建
- 识别需要记录的架构决策
- 使用标准模板创建 ADR
- 状态设置为"提议中"
- 提交 PR 并邀请相关人员评审

### 4.2 评审
- 相关团队成员评审 ADR
- 讨论决策的合理性和后果
- 必要时修改 ADR 内容
- 评审通过后状态改为"已接受"

### 4.3 实施
- 按照 ADR 中的决策实施
- 实施过程中发现问题应更新 ADR
- 实施完成后在 ADR 中记录实际结果

### 4.4 废弃或替代
- 决策不再适用时，状态改为"已废弃"
- 被新决策替代时，状态改为"已替代"，并关联新 ADR
- 废弃的 ADR 不得删除，保留历史记录

## 5. ADR 索引

应维护一个 `README.md` 文件作为 ADR 索引：
```markdown
# 架构决策记录索引

| 编号 | 标题 | 状态 | 日期 |
|------|------|------|------|
| [ADR-0001](ADR-0001-use-postgresql-as-primary-database.md) | 使用 PostgreSQL 作为主数据库 | 已接受 | 2025-01-10 |
| [ADR-0002](ADR-0002-adopt-microservices-architecture.md) | 采用微服务架构 | 已接受 | 2025-01-12 |
| [ADR-0003](ADR-0003-use-redis-for-caching.md) | 使用 Redis 作为缓存 | 已接受 | 2025-01-15 |
```

## 6. 何时创建 ADR

以下情况应创建 ADR：
- 选择技术栈或框架
- 定义系统架构模式（单体/微服务/Serverless）
- 选择数据存储方案
- 定义 API 设计风格（REST/GraphQL/gRPC）
- 选择部署模式（容器/虚拟机/Serverless）
- 定义安全策略
- 选择第三方服务或云服务
- 重大重构或架构演进

## 7. 验证重点

- 重大架构决策是否有对应的 ADR
- ADR 是否使用标准模板
- ADR 是否包含上下文、决策、后果、替代方案
- ADR 是否有明确的状态
- 废弃的 ADR 是否保留历史记录
- 是否维护 ADR 索引
