# 架构设计物料约束

## 1. 默认原则

- 架构决策应文档化，形成可追溯的决策记录（ADR）。
- 架构设计应分层表达：上下文 → 容器 → 组件 → 代码（C4 模型）。
- 技术选型应基于明确的评估标准，而非个人偏好。
- 架构变更应经过评审，重大变更应有 RFC 流程。
- 架构文档应与代码同步演进，避免文档腐化。

## 2. 子文件索引

激活本域时，以下子文件全部生效：

| 子文件 | 覆盖范围 |
|--------|---------|
| `adr.md` | 架构决策记录（ADR）标准与模板 |
| `c4-model.md` | C4 模型图表标准（Context/Container/Component/Code） |
| `rfc.md` | RFC（Request for Comments）流程与模板 |
| `tech-selection.md` | 技术选型评估标准与决策矩阵 |
| `design-review.md` | 设计评审流程与检查清单 |

## 3. 验证重点

- 重大架构决策是否有 ADR 记录
- 架构图是否使用 C4 模型分层表达
- 技术选型是否有评估记录
- 重大变更是否经过 RFC 流程
- 设计评审是否有记录和行动项
