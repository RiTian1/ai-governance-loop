# 原生运行时与跨集成边界

## 1. 默认原则

- 平台差异、服务器集成差异和运行时初始化差异应尽量收敛在明确边界内。
- 共享规则语义与配置处理不应被各集成入口各自复制实现。

## 2. 设计要求

- 修改前先判断变更位于核心运行时、适配层还是第三方基线。
- 影响跨平台或跨服务器行为时，应说明哪些入口会被波及。
- 公共行为优先沉到共享层，不通过局部分支长期维持一致性。

## 3. 初始化与生命周期

- 运行时初始化顺序必须显式声明，不依赖隐式加载顺序。
- 资源获取与释放必须对称（打开/关闭、分配/回收）。
- 初始化失败必须有明确的错误信息和回退策略。

## 4. 版本兼容

- 公共 API 变更必须遵循语义化版本。
- 废弃 API 必须标注 deprecation 警告和替代方案。
- 运行时版本矩阵（支持的平台/语言版本）必须文档化。

## 5. 跨平台一致性

- 平台差异必须在适配层处理，不允许散落在业务逻辑中。
- 跨平台测试矩阵必须覆盖所有声明支持的平台。
- 平台特有行为必须文档化并有对应测试。

## 6. 验证重点

- 是否引入不同集成入口之间的行为漂移
- 是否破坏初始化、资源释放或错误处理路径
- 是否需要补共享测试、适配测试或兼容性说明
- 初始化顺序是否有显式声明
- API 废弃是否有迁移路径
- 跨平台测试是否覆盖声明的平台列表
