# 配置治理约束

## 1. 默认原则

- 配置是产品行为的外化定义，与代码同等重要。
- 所有配置必须版本控制，可审计、可回溯。
- 配置变更应独立于代码变更，但遵循相同的审批和门禁流程。
- 配置应分层管理：基础配置 → 环境配置 → 运行时配置。
- 敏感配置（密钥、凭据）必须与普通配置分离管理。

## 2. 子文件索引

激活本域时，以下子文件全部生效：

| 子文件 | 覆盖范围 |
|--------|---------|
| `config-formats.md` | 配置文件格式标准（YAML/JSON/TOML/ENV/INI） |
| `config-layering.md` | 配置分层策略（base/dev/staging/prod） |
| `feature-flags.md` | 特性开关标准（定义、生命周期、清理） |
| `secrets-config.md` | 密钥与敏感配置管理（注入、轮换、审计） |
| `env-variables.md` | 环境变量命名与管理规范 |

## 3. 验证重点

- 配置文件是否版本控制
- 敏感配置是否与普通配置分离
- 配置分层是否合理
- 环境变量命名是否规范
- 特性开关是否有生命周期管理
