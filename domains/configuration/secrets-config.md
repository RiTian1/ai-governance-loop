# 密钥与敏感配置管理

## 1. 密钥分类

### 1.1 按敏感等级
- **Critical**：生产数据库密码、支付 API 密钥、签名证书私钥
- **High**：第三方服务 API 密钥、OAuth Client Secret、加密密钥
- **Medium**：内部服务间认证 Token、SMTP 密码
- **Low**：开发环境密钥、测试 API 密钥

### 1.2 按生命周期
- **长期密钥**：签名证书、加密主密钥（定期轮换）
- **短期密钥**：Access Token、Session Key（自动过期）
- **一次性密钥**：临时 Token、OTP（使用后销毁）

## 2. 存储规范

### 2.1 绝对禁止
- 禁止将密钥硬编码到源代码中
- 禁止将密钥提交到版本控制系统（Git）
- 禁止将密钥写入日志、错误消息或监控指标
- 禁止通过即时通讯工具（Slack, 微信）传递密钥
- 禁止将密钥存储在共享文档或 Wiki 中

### 2.2 推荐存储
- **密钥管理服务**（推荐）：HashiCorp Vault, AWS Secrets Manager, Azure Key Vault, GCP Secret Manager
- **CI/CD 密钥存储**：GitHub Secrets, GitLab CI Variables（Protected）
- **开发环境**：.env 文件（已加入 .gitignore）或本地密钥管理器

### 2.3 防泄漏措施
- `.gitignore` 中必须包含：`.env`, `*.pem`, `*.key`, `*.p12`, `credentials.*`
- 应配置 Git pre-commit hook 扫描密钥泄漏（如 detect-secrets, gitleaks）
- 应定期扫描 Git 历史中的密钥泄漏
- 发现泄漏后应立即轮换受影响密钥

## 3. 注入机制

### 3.1 运行时注入（推荐）
- 通过环境变量注入
- 通过密钥管理服务 SDK 拉取
- 通过 Kubernetes Secrets 挂载
- 通过 sidecar 模式注入（如 Vault Agent）

### 3.2 构建时注入（谨慎使用）
- CI/CD 流水线中通过受保护变量注入
- 禁止在构建产物中残留密钥
- 构建日志应自动掩码密钥值

## 4. 轮换策略

### 4.1 轮换周期
- Critical 密钥：至少每 90 天轮换一次
- High 密钥：至少每 180 天轮换一次
- Medium 密钥：至少每 365 天轮换一次
- 发生安全事件后：立即轮换所有相关密钥

### 4.2 自动轮换
- 应尽可能实现自动轮换（密钥管理服务支持）
- 轮换过程应零停机（支持双密钥过渡期）
- 轮换后应自动通知依赖方

### 4.3 轮换记录
- 所有轮换操作必须记录审计日志
- 日志应包含：轮换时间、操作人、旧密钥标识（非密钥值）
- 审计日志应不可篡改

## 5. 访问控制

- 密钥访问应遵循最小权限原则
- 应记录谁在什么时间访问了哪个密钥
- 应定期审计密钥访问权限
- 人员离职或角色变更后应立即撤销密钥访问权限

## 6. 验证重点

- 源代码和 Git 历史中是否存在硬编码密钥
- .gitignore 是否包含常见密钥文件模式
- 是否配置了 pre-commit 密钥扫描
- 密钥轮换是否按周期执行
- 是否使用密钥管理服务而非明文存储
- 日志和错误消息中是否泄漏密钥
