# 数据库领域约束

## 1. 默认原则

- 结构变更通过明确迁移管理，不依赖隐式兼容。
- 读模型、写模型、审计模型如有必要应显式分离。
- 领域对象不直接等同于持久化表结构。

## 2. 约束

- Schema 变更必须具备迁移路径、回滚策略与版本说明。
- 查询优化不应以破坏领域边界为代价。
- 配置、环境、租户差异等动态数据不得硬编码在查询层。

## 3. 索引与查询优化

- 外键必须有对应索引。
- 频繁查询的过滤字段应有索引覆盖，新索引需评估写入影响。
- 禁止 `SELECT *`，必须显式列出字段。
- 慢查询阈值必须配置并监控（建议 > 200ms 告警）。

## 4. 连接与资源管理

- 必须使用连接池，禁止每次请求新建连接。
- 连接池大小应基于并发量和数据库承载能力配置。
- 长事务必须设置超时，禁止无限期持有连接。

## 5. 备份与恢复

- 必须有定期备份策略（频率、保留期、存储位置）。
- 备份恢复流程必须定期演练并记录结果。
- 生产数据用于开发/测试前必须脱敏。

## 6. 验证重点

- 迁移是否可重复执行
- 数据兼容与回滚是否有证据
- 性能优化是否绕过了正常抽象边界
- 索引是否覆盖高频查询路径
- 连接池配置是否匹配负载预期
- 备份恢复是否在最近 N 周内演练过
