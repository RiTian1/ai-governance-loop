# 构建制品与发布门禁

## 1. 默认原则

- 构建应可复现：相同源码、相同环境应产出相同制品。
- 制品应可追溯：每个制品应关联源码版本、构建时间、构建环境。
- 发布应有门禁：未通过质量门禁的制品不得进入生产环境。
- 环境应分层治理：开发、测试、预发布、生产环境应有明确边界和准入规则。
- 基础设施应代码化：环境配置、部署流程应以代码形式版本控制。

## 2. 子文件索引

## 3. 验证重点

- 构建是否可复现
- 制品是否包含完整元数据（版本、commit、时间戳）
- CI/CD 是否配置质量门禁
- 环境配置是否代码化且版本控制
- 部署是否有回滚预案
- OpenSpec 归档提交是否满足 `02-engineering-principles.md` §10（归档目录与实现同 commit、已 push `origin/master`）

## 4. 与全局约束的衔接

- 编码：仓库与 CI 日志 UTF-8 见 `coding-standards.md` §6（落实全局 §9）。
- 交付：本域负责 pipeline/发布门禁；归档原子提交纪律以工程原则 §10 为准。
