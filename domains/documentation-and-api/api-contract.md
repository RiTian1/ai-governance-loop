# API 契约约束

## 1. 规范版本与格式

- RESTful API 必须使用 OpenAPI 3.0+ 规范描述，禁止使用 Swagger 2.0。
- 事件驱动 API 必须使用 AsyncAPI 2.0+ 规范描述。
- gRPC 服务必须提供 `.proto` 文件，且 `.proto` 文件必须纳入版本控制。
- 契约文件格式应优先使用 YAML（可读性优先），JSON 作为备选。

## 2. 契约优先开发

- 必须遵循契约优先（Contract-First）原则：先定义契约，再实现代码。
- 禁止先写代码再反向生成契约文件，除非是对遗留系统的首次契约化。
- 契约文件应作为前后端、服务间协作的唯一权威接口定义。

## 3. 版本兼容性

- API 版本必须遵循语义化版本（SemVer）：MAJOR.MINOR.PATCH。
- MINOR 版本升级必须保持向后兼容，不得删除或修改已有字段语义。
- 废弃（Deprecated）字段或端点必须标注废弃版本和预计移除版本，废弃周期不得少于 2 个 MINOR 版本。
- MAJOR 版本升级必须提供迁移指南文档。

## 4. 自动生成与验证

- 契约文件应可自动生成客户端 SDK 和服务端存根，生成工具应在项目文档中声明。
- CI 流水线必须包含契约校验步骤，实现代码与契约不一致时应阻断构建。
- 契约变更后，Mock 服务必须同步更新，确保前端/消费方可立即使用最新契约进行开发。

## 5. 文档与示例

- 每个端点/方法必须包含描述（description）、请求示例和响应示例。
- 错误码必须在契约中统一定义，禁止在代码中硬编码未声明的错误码。
- 认证与授权方式必须在契约的 securitySchemes 中明确声明。

## 6. 验证重点

- 契约文件是否使用指定规范版本（OpenAPI 3.0+/AsyncAPI 2.0+）
- 是否遵循契约优先原则
- 版本兼容性规则是否落实（废弃声明、迁移指南）
- CI 是否包含契约校验步骤
- 端点是否包含描述和示例
