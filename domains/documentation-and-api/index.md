# 文档与接口说明约束

## 1. 默认原则

- 配置、集成、构建和使用方式的文档是交付的一部分，不是附属品。
- 影响外部使用者的改动，应同步更新 README、集成说明或接口文档。
- 文档应说明适用范围、前置条件、关键参数和限制条件。
- 变更若影响规则、配置或集成方式，应明确兼容性影响。
- 示例命令、路径和文件名应尽量与仓库现实一致。

## 2. 物料格式约束

不同格式的文档物料有各自的结构和质量要求。激活本域时，以下子文件全部生效：

| 子文件 | 覆盖范围 |
|--------|---------|
| `markdown.md` | Markdown 写作规范 |
| `visual-formats.md` | 图表与可视化（drawio/mermaid/svg/png） |
| `mindmap.md` | 脑图约束 |
| `spreadsheet.md` | 表格与结构化数据（Excel/CSV） |
| `api-contract.md` | API 契约（OpenAPI/AsyncAPI/Protobuf） |
| `changelog.md` | 变更日志与版本记录 |

## 3. 结构化可视展示

在最终结果物料中，如有图表/数据分析/流程展示需求，必须在物料中以结构化方式体现。
格式包含但不限于：png、svg、drawio、html、gif。html 等综合页面可以调用嵌套其他格式数据。

## 4. 验证重点

- 文档是否覆盖实际改动影响面
- 使用者是否能据此完成最小操作路径
- 物料格式是否符合对应子文件的约束
