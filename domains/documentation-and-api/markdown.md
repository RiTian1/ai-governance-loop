# Markdown 写作规范

## 1. 标题层级

- 每个文档必须有且仅有一个 H1（`#`）作为文档标题。
- H2（`##`）用于主要章节划分，H3（`###`）用于子节，H4（`####`）用于细分项。
- 禁止跳级使用标题（例如 H2 直接跳到 H4）。
- 不得在标题中使用内联代码块或链接，标题应为纯文本。
- H4 以下层级应考虑改用列表或表格替代，避免层级过深。

## 2. Front Matter 与元数据

- 规范文档、架构文档和 PRD 必须包含 YAML Front Matter，至少声明 `title`、`date`、`status` 字段。
- Front Matter 中的日期格式必须为 ISO 8601（`YYYY-MM-DD`）。
- 应在 Front Matter 中标注文档所属域或模块，便于索引检索。

## 3. 链接与引用

- 仓库内引用必须使用相对路径，禁止使用绝对路径或硬编码域名。
- 外部链接应标注访问日期或版本号，防止链接失效后无法溯源。
- 每次发布前应执行死链检查，存在死链的文档不得合入主分支。

## 4. 代码块与表格

- 代码块必须指定语言标识符（如 ```python、```yaml），禁止使用无标注的裸代码块。
- 表格必须使用标准 Markdown 管道语法，表头与分隔行不得省略。
- 表格列对齐应保持一致（左对齐或居中），同一文档内风格统一。

## 5. 文件命名与格式

- Markdown 文件名必须使用 kebab-case，全小写，禁止空格和大写字母。
- 单行长度建议不超过 120 个字符（软限制），超长行应合理换行。
- 文件末尾必须保留一个空行，符合 POSIX 标准。

## 6. 验证重点

- 标题层级是否连续、H1 是否唯一
- 代码块是否全部标注语言
- 仓库内链接是否均为相对路径且可达
- 文件命名是否符合 kebab-case 规范
