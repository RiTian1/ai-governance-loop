# 脑图约束

## 1. 工具与格式要求

- 推荐使用 XMind、FreeMind 或 Markmap 创建脑图。
- 必须同时提交可版本控制的源格式（`.md`、`.json`、`.mm`、`.xmind`）和可视化导出格式（`.png` 或 `.svg`）。
- 禁止仅提交截图或不可编辑的图片作为脑图交付物。

## 2. 结构与层级

- 脑图层级深度建议不超过 4 层，超过 4 层应拆分为多张子脑图。
- 根节点必须明确标注主题名称和创建日期。
- 每个节点的文字应简洁，建议不超过 15 个字，优先使用动词短语。
- 同一层级的兄弟节点应保持语义粒度一致，禁止粗细混杂。

## 3. 内容约束

- 脑图中不得包含敏感信息、密钥或个人隐私数据。
- 关键节点应附带简要备注说明，避免仅靠标题传达含义。
- 节点间的关联关系（如依赖、冲突）应使用连线或标注明确表达。

## 4. 适用与不适用场景

- 适用场景：需求探索、知识梳理、架构头脑风暴、方案对比。
- 不适用场景：详细设计文档、精确数据记录、流程控制逻辑、正式接口定义。
- 脑图作为探索工具使用后，其结论必须沉淀为正式文档，脑图本身不得作为唯一交付物。

## 5. 验证重点

- 是否同时提交了源文件和可视化导出
- 层级深度是否超过 4 层
- 节点命名是否简洁、粒度是否一致
- 是否存在敏感信息
- 探索结论是否已沉淀为正式文档
