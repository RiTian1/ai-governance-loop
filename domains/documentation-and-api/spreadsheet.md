# 表格与结构化数据约束

## 1. Sheet 命名与组织

- Sheet/工作表必须使用描述性名称，禁止使用默认名称（如 Sheet1、Sheet2、工作表1）。
- Sheet 名称应使用中文或 kebab-case 英文，长度不超过 31 个字符。
- 多 Sheet 文件必须在第一个 Sheet 中提供目录说明各 Sheet 的用途。

## 2. 数据结构要求

- 首行必须为表头行，表头文字应简洁明确，禁止留空。
- 数据区域禁止使用合并单元格，合并单元格仅允许用于展示层标题区。
- 同一列的数据类型必须保持一致（数字列不得混入文本，日期列不得混入自由格式）。
- 每个数据表应包含唯一标识列（ID/序号），便于引用和追溯。

## 3. 格式选择

- 纯数据交换场景必须优先使用 CSV 或 TSV 格式，确保可 diff 和版本控制。
- Excel（.xlsx）仅在需要多 Sheet、公式计算、数据验证或条件格式时使用。
- 禁止使用 .xls（旧格式），必须使用 .xlsx。
- CSV 文件必须使用 UTF-8 编码，首行为表头。

## 4. 安全与敏感数据

- 禁止在表格文件中硬编码密码、API 密钥、令牌或其他凭据。
- 包含个人身份信息（PII）的表格必须标注数据分类等级并限制访问权限。
- 提交到版本控制的表格不得包含生产环境真实数据，应使用脱敏或模拟数据。

## 5. 适用场景

- 适用场景：对比矩阵、配置清单、测试用例表、数据字典、权限矩阵。
- 不适用场景：长篇叙述性内容、流程描述、架构说明（应使用 Markdown 或图表）。

## 6. 验证重点

- Sheet 命名是否具有描述性
- 首行表头是否完整、数据类型是否一致
- 是否存在不必要的合并单元格
- 是否包含敏感数据或硬编码凭据
- 格式选择是否合理（CSV vs Excel）
