# 图表与可视化约束

## 1. drawio 规范

- 提交 drawio 图表时，必须同时提交 `.drawio` 源文件和导出的 `.svg` 或 `.png` 文件。
- `.drawio` 源文件必须纳入版本控制，禁止仅提交导出图片而遗漏源文件。
- 导出图片应与源文件保持同步，源文件变更后必须重新导出。

## 2. mermaid 规范

- 简单图表应优先以 mermaid 代码块嵌入 Markdown，便于版本控制和差异对比。
- 复杂图表（节点超过 30 个或嵌套超过 3 层）可导出为 svg/png，但必须保留 `.mmd` 源文件。
- mermaid 代码块必须标注 ```mermaid 语言标识符。

## 3. svg 规范

- svg 文件中的文本必须内嵌字体或使用系统通用字体，禁止外链字体，保证离线可读。
- svg 应保持可编辑性，不得将文本转换为路径（除非有特殊排版需求并注明原因）。
- 应为 svg 图表提供简要的文字说明或 alt 描述。

## 4. png/gif 规范

- png 图片分辨率最低为 2x（即逻辑尺寸的两倍像素），确保高清屏可读。
- 单个 png/gif 文件大小不得超过 2MB，超出应压缩或改用 svg。
- 在 Markdown 中引用 png/gif 时，必须附带 alt text 描述图片内容。
- gif 仅用于演示操作流程，禁止用于静态内容展示。

## 5. 命名与版本管理

- 图表文件命名约定：`[文档名]-[图表类型]-[序号].[ext]`，例如 `arch-overview-sequence-01.svg`。
- 所有源文件（`.drawio`、`.mmd`、`.svg` 可编辑版）必须纳入版本控制。
- 禁止在仓库中存放未被任何文档引用的孤立图片文件。

## 6. 验证重点

- drawio 是否同时提交了源文件和导出文件
- svg 文本是否内嵌字体、离线可读
- png/gif 是否满足分辨率和大小要求
- 所有图片是否附带 alt text
- 命名是否符合约定格式
