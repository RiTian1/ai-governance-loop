# 前端领域约束

## 1. 适用范围

适用于 Web 前端、客户端页面层、组件树、前台状态管理与文案系统。

## 2. 默认原则

- 页面负责场景编排，组件负责局部展示与意图发出。
- 共享状态放在受控边界，局部交互状态保留在实例级。
- 复用优先通过组合与配置，而不是复制组件分支。

## 3. 状态与数据流

- 远端数据、派生视图状态、局部交互状态分层管理。
- 页面不得直接感知底层平台差异；平台差异应由适配层吸收。
- 文案、主题、用户偏好等跨页面状态优先集中建模。

## 4. 文案与本地化

- 高可见文案不应散落在组件内硬编码。
- 本地化边界需要能表达语言、区域、白名单原文与回退策略。

## 5. 无障碍与可访问性

- WCAG 2.1 AA 级别为默认要求。
- 交互元素必须支持键盘操作和焦点管理。
- 图片和图标必须有 alt text 或 aria-label。
- 色彩对比度必须满足 4.5:1（正文）/ 3:1（大文本）。

## 6. 性能预算

- 首屏 JavaScript Bundle 大小应有上限（如 < 200KB gzipped）。
- 图片应使用 WebP/AVIF 格式，设置 srcset 响应式加载。
- CSP（Content Security Policy）应配置并禁止 inline script。

## 7. 视觉/交互变更的验收标准前置（DoD-first）

> 字段实战教训：一个资源关系图（overview）从 `overview.png` 反复截图迭代到 `overview20.png`，
> 近两周都在「遮挡 / 连线交叉 / 卡顿 / 不居中 / 不好看」之间来回返工——根因是**没有前置量化验收标准**，
> Agent 在没有明确契约时只能盲目试错，烧掉大量 token 与时间。

- 涉及**布局 / 视觉 / 交互**的变更（尤其画布、图可视化、复杂列表），实施前必须先定**量化验收基线**，例如：
  - 布局：节点/卡片无重叠、连线无交叉或交叉数 ≤ 阈值、层级对齐、点击后目标居中可见。
  - 交互：单击/双击语义明确不互相误触发、展开/收缩可预期、选中态有醒目视觉。
  - 性能：节点数上限、目标帧率 / 首次可交互时间、切换无明显卡顿的量化门。
- 没有可判定的验收标准，不进入 apply。禁止「先随便做一版看看效果」再无限次截图返工。
- 验收标准写入变更的 spec/tasks 或 story 的 Acceptance Criteria，作为完成判定依据。

## 8. 验证重点

- 组件在不同状态下是否仍保持独立
- 页面切换与路由切换是否有可审计证据
- 文案、主题、尺寸变化是否不会击穿布局
- 无障碍审计（axe/Lighthouse）是否零违规
- Bundle 大小是否在预算内
- CSP 是否配置且无 unsafe-inline
- 视觉/交互变更是否有前置量化验收基线（§7），而非截图试错
