# GUI 领域约束

## 1. 适用范围

适用于桌面 GUI、图形化工作台、可视化编辑器、测试工作台、窗口壳等交互密集界面。

## 2. 默认最佳实践

- 复杂交互采用“输入适配 -> 事件派发 -> 控制器/状态机 -> 状态更新 -> 视图绑定”。
- 视图层尽量保持薄，只负责表达状态和发出意图。
- 多控件共享的拖拽、缩放、hover、焦点、标题栏交互优先走共享控制器。

## 3. 布局约束

- 父子控件尺寸与位置关系应有稳定约束，不允许依赖隐式魔法数拼接。
- 可扩展的展示面默认支持纵向或横向滚动，不应把内容截断成不可见区域。
- 文本、图标、子控件应随父对象变化保持可读与可操作。
- 检查布局时，默认关注重叠、遮挡、截断、越界、不可点击区域。

## 4. 交互约束

- 分割条、拖拽边、标题栏等区域必须保持连续指针捕获，直到释放。
- 点击、按下、悬停、离开、双击、滚动等语义应明确区分，不应互相串扰。
- 一个控件实例的事件状态不应意外污染其他实例。
- 命中区域、交互区域、视觉区域不一致时，必须能通过诊断数据解释。

## 5. 状态约束

- GUI 壳状态、页面状态、控件实例状态、临时编辑状态应分层存放。
- 对同一责任域，优先建立单一权威状态源，避免影子字段和镜像状态。

## 6. 文案与多语言

- 用户可见文案默认走集中式文案边界。
- 字体、字号、截断策略、排版间距应考虑多语言长度差异。

## 7. 验证重点

- 自动化是否能拿到实例级几何、命中、状态与文本信息
- release 形态是否仍可输出诊断证据
- 人工式事件回放是否能覆盖拖拽、hover、滚动、点击和页面切换
