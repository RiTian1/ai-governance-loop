# 告警规则与管理

## 1. 告警分级

### 1.1 严重等级定义
| 等级 | 说明 | 响应时间 | 通知方式 | 示例 |
|------|------|---------|---------|------|
| P0 - Critical | 服务完全不可用 | 立即（5 分钟内） | 电话 + 短信 + IM | 数据库宕机、支付服务不可用 |
| P1 - High | 核心功能受损 | 15 分钟内 | 短信 + IM | 错误率 > 5%、P99 延迟超 SLO 2 倍 |
| P2 - Medium | 非核心功能异常 | 1 小时内 | IM + 邮件 | 缓存失效、非关键 API 错误率升高 |
| P3 - Low | 潜在问题 | 工作时间内处理 | 邮件 | 磁盘使用率 > 70%、依赖版本过期 |
| P4 - Info | 信息通知 | 无需响应 | Dashboard | 部署完成、配置变更 |

### 1.2 分级原则
- 影响用户核心业务流程 → P0/P1
- 影响内部运维或非核心功能 → P2/P3
- 仅供参考的信息 → P4

## 2. 告警规则设计

### 2.1 基于 SLO 的告警
- 错误预算消耗速率告警：
  - 快速消耗（1 小时内消耗 2% 预算）→ P1
  - 中速消耗（6 小时内消耗 5% 预算）→ P2
- 错误预算余额告警：
  - 剩余 < 10% → P2
  - 剩余 < 5% → P1

### 2.2 症状告警 vs 原因告警
- **优先症状告警**（用户视角）：
  - 错误率 > 1%
  - P99 延迟 > 500ms
  - 可用性 < 99.9%
- **辅助原因告警**（系统视角）：
  - CPU 使用率 > 80%
  - 内存使用率 > 90%
  - 磁盘 I/O 饱和

### 2.3 告警阈值设置
- 阈值应基于历史数据和 SLO 设定
- 使用动态阈值（基于历史趋势）而非静态阈值
- 避免过于敏感的阈值（导致告警疲劳）
- 阈值应定期复盘和调整

## 3. 告警消噪

### 3.1 抑制（Suppression）
- 维护窗口期间抑制告警
- 已知问题期间抑制重复告警
- 下游服务故障时抑制上游告警

### 3.2 聚合（Aggregation）
- 同一服务的多个实例告警聚合为一条
- 同一根因的多个告警聚合为一条
- 时间窗口内的重复告警去重

### 3.3 静默（Silencing）
- 临时静默特定告警（如已知问题修复中）
- 静默应有明确的过期时间
- 静默应记录原因和负责人

## 4. 告警通知

### 4.1 通知渠道
- P0/P1：电话 + 短信 + IM（Slack, 钉钉, 企业微信）
- P2：IM + 邮件
- P3/P4：邮件 + Dashboard

### 4.2 通知内容
告警通知应包含：
- 告警等级和服务名称
- 告警摘要（一句话描述问题）
- 当前值和阈值
- 影响范围（用户数、请求数）
- Runbook 链接（处理步骤）
- Dashboard 链接（查看详情）
- 相关日志/追踪链接

### 4.3 通知示例
```
[P1] order-service 错误率异常

当前错误率：5.2%（阈值：1%）
影响：约 500 个请求失败
持续时间：5 分钟

Runbook: https://wiki.example.com/runbooks/order-service-errors
Dashboard: https://grafana.example.com/d/order-service
Logs: https://kibana.example.com/...
```

## 5. 值班与升级

### 5.1 值班轮换
- 应有明确的值班排班表
- 值班人员应有备份（Primary + Secondary）
- 值班交接应有交接记录

### 5.2 升级机制
- P0 告警：5 分钟无响应自动升级到 Secondary
- P1 告警：15 分钟无响应自动升级
- 升级路径：值班工程师 → 团队 Lead → 部门负责人

## 6. 告警复盘

### 6.1 告警质量指标
- 告警准确率：真实问题 / 总告警数（目标 > 90%）
- 告警响应时间：从告警到确认的时间
- 告警解决时间：从告警到问题解决的时间
- 告警疲劳度：每人每天收到的告警数（目标 < 10）

### 6.2 定期复盘
- 每周复盘：误报告警、漏报告警
- 每月复盘：告警规则优化、阈值调整
- 每季度复盘：告警体系整体评估

## 7. 验证重点

- 告警是否分级且响应时间明确
- 是否基于 SLO 设置告警
- 是否优先症状告警而非原因告警
- 是否配置了告警消噪机制
- 告警通知是否包含 Runbook 和 Dashboard 链接
- 是否有值班轮换和升级机制
- 是否定期复盘告警质量
