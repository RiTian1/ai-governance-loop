# 可观测性约束

## 1. 默认原则

- 日志、指标、链路追踪应协同设计，而不是各自孤立生长。
- 关键用户路径、关键后台作业、关键副作用应有最小可观测性覆盖。
- 结构化数据优先于自由文本。
- 可观测性数据应支持事故复盘，而不是只适合实时看板。
- 重要故障应能形成可审计证据链。

## 2. 子文件索引

激活本域时，以下子文件全部生效：

| 子文件 | 覆盖范围 |
|--------|---------|
| `logging.md` | 日志格式、级别、结构化日志、脱敏 |
| `metrics.md` | 指标命名、采集、SLO/SLI 定义 |
| `tracing.md` | 分布式追踪、Span 标准、上下文传播 |
| `alerting.md` | 告警规则、分级、通知、消噪 |
| `incident.md` | 事故响应、复盘、RCA 报告、证据链 |

## 3. 三支柱协同

### 3.1 关联性要求
- 日志、指标、追踪应通过统一标识（如 Trace ID）关联
- 从告警到日志到追踪应有完整的下钻路径
- 可观测性工具链应支持跨信号（cross-signal）查询

### 3.2 最小可观测性覆盖
每个服务/组件应至少具备：
- 健康检查端点（liveness, readiness）
- 请求日志（入站/出站）
- 核心业务指标（延迟、吞吐、错误率）
- 错误告警（错误率超阈值）

## 4. 验证重点

- 是否能定位关键故障
- 是否能解释性能退化
- 日志、指标、追踪是否通过统一标识关联
- 是否支撑人工与自动化验证的证据需求
