# 晋升与淘汰（`proj.orch.r2` / `r5` / `r6`）

## 什么算"一次成功"（`r2`）

没有产出证据的完成叫 **inert success**：跑了、没报错、什么也没变。
它**不计入晋升统计**。

四类产出证据（四类之一即可）：

| 类型 | 判据 |
|---|---|
| 变更差异 | 文件数 > 0 或行数 > 0 |
| 产物摘要 | 有 sha256 |
| 外部回执 | 有回执 id |
| 工具调用轨迹 | 调用次数 > 0 |

为什么这条重要：agent 最容易"自我确认"——复述一遍结论就当完成。
不把 inert 剔出去，晋升出来的规则全是"说过的话"，不是"做过的事"。

## 晋升门槛

```
失败次数 == 0  且  真实产出成功次数 >= 3
```

`失败次数 == 0` 是硬条件：挂过一次就再也不会自动晋升（累计，不可稀释）。
这条很激进——宁可漏掉好经验，不放一条挂过的进主干。

## 淘汰：硬闸先判死（`r5`）

先判资格，再谈排序。被硬条件拒掉的对象**不会因为历史表现好而复活**。

对应到治理的常见失败模式：某条规则"以前很有用"，于是在该淘汰时被网开一面。
一旦开了这个口子，淘汰机制就等于不存在。

## 只从执行提炼，不从对话蒸馏（`r6`）

实测数据（来自所依据的逆向对象）：从"真实跑通过一次"提炼的经验，
比从"事后总结对话"提炼的高 3~11 个百分点。

推论：会话本身不是规则来源，**带产出证据的会话才是**。
所以提炼入口必须挂在"有产物/有变更/有回执"的轮次上，而不是任意对话。
