# 性能与响应性约束

## 1. 默认原则

- 启动、首帧、输入响应、页面切换、拖拽连续性、动画流畅度是架构问题，不是收尾打磨问题。

## 2. 约束

- 非 correctness-critical 工作默认不阻塞关键交互路径。
- 长耗时任务优先预加载、后台加载、懒加载、分阶段初始化、渐进呈现。
- 若工作未完成，界面必须给出过渡态，而不是像假死。

## 3. 性能指标与基准

- 必须定义性能 SLO（P50/P95/P99 响应时间）。
- 关键操作必须有基准测试，结果纳入 CI 回归。
- 内存/CPU 使用应有预算上限，超出触发告警。

## 4. CI 性能门禁

- 性能回归测试应集成到 CI 流水线。
- 性能退化超过阈值（如 P95 退化 > 10%）应阻断合并。
- 基准测试结果应可追溯（保留历史趋势）。

## 5. 容量规划

- 预期用户量/请求量变化时必须重新评估容量。
- 压力测试应覆盖预期峰值的 2x 负载。
- 性能优化应量化收益，避免过早优化。

## 6. 验证重点

- 首帧是否可交互
- 页面切换是否仍能持续响应
- 拖拽和分割条是否连续
- 动画是否因主线程阻塞而掉帧
- release 与 debug 的表现差异是否被记录
- SLO 是否定义并监控
- 基准测试是否在 CI 中自动运行
- 容量规划是否覆盖预期增长
