# 认证与访问控制

## 1. 认证协议选择

- 面向用户的 Web 应用优先采用 OAuth 2.0 + OIDC 协议，禁止自行实现认证协议。
- 无状态 API 服务使用 JWT 作为令牌格式，令牌必须包含签发时间（iat）、过期时间（exp）和受众（aud）声明。
- 传统 Web 应用可使用 Session 机制，但必须配合 CSRF 防护。
- 移动端应用使用 PKCE 扩展的 OAuth 2.0 授权码流程，禁止使用隐式授权流程。
- 所有认证端点必须强制 HTTPS，禁止明文传输凭据。

## 2. 鉴权模型设计约束

- 默认采用 RBAC（基于角色的访问控制），角色定义必须遵循最小权限原则。
- 需要细粒度动态策略时采用 ABAC（基于属性的访问控制），策略规则必须集中管理。
- ACL 仅用于资源级别的个体授权场景，禁止作为主要鉴权模型。
- 权限变更必须经过审批流程并记录审计日志。
- 鉴权逻辑必须在服务端执行，客户端鉴权仅用于 UI 展示优化，不可作为安全屏障。

## 3. 多因素认证（MFA）要求

- 管理后台、运维控制台等高权限入口必须强制启用 MFA。
- 普通用户账户应提供 MFA 选项，涉及资金或敏感数据操作时强制要求。
- MFA 方式优先级：硬件安全密钥 > TOTP 应用 > 短信验证码。
- MFA 恢复流程必须经过身份核验，禁止仅凭邮箱重置。

## 4. 令牌生命周期管理

- 访问令牌（Access Token）有效期不超过 15 分钟。
- 刷新令牌（Refresh Token）有效期不超过 7 天，且必须支持单次使用后轮换。
- 令牌吊销接口必须同步生效，不依赖过期时间自然失效。
- JWT 签名算法禁止使用 none 和 HS256（共享密钥），推荐 RS256 或 ES256。
- 令牌存储禁止使用 localStorage，Web 端推荐 HttpOnly + Secure + SameSite Cookie。

## 5. 会话管理

- 会话空闲超时不超过 30 分钟，绝对超时不超过 12 小时。
- 同一账户并发会话数应设上限，超出时终止最早会话或拒绝新登录。
- 会话标识符必须在认证成功后重新生成，防止会话固定攻击。
- 敏感操作（修改密码、绑定 MFA）前必须重新验证身份。
- 登出操作必须同时销毁服务端会话和客户端令牌。

## 6. 服务间认证

- 内部服务间通信优先采用 mTLS（双向 TLS），证书由统一 CA 签发。
- API Key 仅用于低风险的内部集成场景，必须绑定来源 IP 或服务标识。
- Service Account 凭据必须由密钥管理服务托管，禁止硬编码或写入配置文件。
- 服务间调用必须携带调用方身份标识，支持链路级别的访问控制审计。

## 7. 验证重点

- 认证流程是否覆盖所有入口（API、WebSocket、管理后台、CLI）
- 令牌签名算法和有效期是否符合约束
- 高权限操作是否强制 MFA
- 服务间认证凭据是否由密钥管理服务托管
- 会话管理是否防御固定攻击和并发滥用
