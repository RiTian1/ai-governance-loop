# 输入校验与注入防护

## 1. 白名单优先原则

- 所有外部输入必须经过校验，默认策略为拒绝，仅放行符合白名单规则的数据。
- 校验逻辑必须在服务端执行，客户端校验仅作为用户体验优化，不可替代服务端校验。
- 输入校验应在业务逻辑处理之前完成，形成统一的校验层。
- 校验规则必须明确定义允许的字符集、长度范围、格式模式和值域。
- 对于复杂结构化输入，使用 JSON Schema 或等效的声明式校验框架。

## 2. SQL/NoSQL/LDAP/OS 命令注入防护

- SQL 查询必须使用参数化查询或预编译语句，禁止字符串拼接构造查询。
- NoSQL 查询（MongoDB 等）禁止直接将用户输入作为查询操作符，必须校验输入类型。
- LDAP 查询必须对特殊字符（如 `*`、`(`、`)`、`\`、`NUL`）进行转义。
- 禁止将用户输入直接传递给 OS 命令执行函数（如 `exec`、`system`、`popen`）。
- 必须使用命令参数数组形式调用外部进程，避免 shell 解释器介入。

## 3. XSS 防护

- 所有动态输出到 HTML 的内容必须经过上下文感知的输出编码（HTML/JS/CSS/URL）。
- 部署 Content-Security-Policy（CSP）头，禁止 `unsafe-inline` 和 `unsafe-eval`。
- 前端框架应启用自动转义功能（如 React JSX、Vue 模板默认转义）。
- 禁止使用 `innerHTML`、`document.write`、`eval` 等危险 DOM 操作处理用户输入。
- 富文本场景必须使用白名单过滤库（如 DOMPurify），仅允许安全的 HTML 标签和属性。

## 4. 文件上传约束

- 允许上传的文件类型必须使用白名单控制，同时校验文件扩展名和 MIME 类型。
- 单文件大小限制和总上传配额必须明确配置，防止资源耗尽攻击。
- 上传文件必须存储在 Web 根目录之外的隔离存储区，禁止直接通过 URL 访问执行。
- 上传后必须进行病毒/恶意软件扫描，扫描未通过的文件立即删除。
- 文件名必须重新生成（UUID 或哈希），禁止使用用户提供的原始文件名存储。

## 5. 序列化安全

- 禁止对不可信来源的数据进行反序列化操作（Java ObjectInputStream、Python pickle 等）。
- API 数据交换统一使用 JSON 格式，并通过 JSON Schema 校验结构和类型。
- 如必须使用二进制序列化，限定为 Protocol Buffers、FlatBuffers 等类型安全的格式。
- XML 解析必须禁用外部实体（XXE）和 DTD 处理。
- GraphQL 接口必须限制查询深度和复杂度，防止资源耗尽攻击。

## 6. 参数篡改防护

- 涉及金额、数量、权限等关键业务参数，服务端必须独立计算，禁止信任客户端传值。
- 跨服务调用的关键参数应使用 HMAC 或数字签名保护完整性。
- URL 中的资源标识符必须配合鉴权检查，防止 IDOR（不安全的直接对象引用）。
- 批量操作接口必须校验请求数量上限，防止通过参数篡改触发大规模操作。

## 7. 验证重点

- 是否存在未经校验直接进入业务逻辑的外部输入
- SQL/NoSQL 查询是否全部使用参数化方式
- CSP 策略是否已部署且禁止 unsafe-inline
- 文件上传是否执行类型白名单和隔离存储
- 反序列化操作是否限定为类型安全的格式
