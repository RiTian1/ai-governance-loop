# 密钥与敏感配置管理

## 1. 硬编码密钥禁令

- 源代码中禁止出现任何形式的密钥、密码、令牌、连接字符串等敏感信息。
- 文档、注释、示例代码中禁止包含真实的敏感配置值，必须使用占位符（如 `<YOUR_API_KEY>`）。
- 日志输出禁止记录密钥、令牌、密码等敏感字段，必须在日志框架层面统一脱敏。
- .env 文件禁止提交到版本控制，必须通过 .gitignore 排除并提供 .env.example 模板。
- 错误响应和异常堆栈禁止向客户端暴露敏感配置信息。

## 2. 密钥管理服务要求

- 生产环境密钥必须由专用密钥管理服务（KMS/HashiCorp Vault/AWS Secrets Manager 等）托管。
- 应用程序通过 API 动态获取密钥，禁止将密钥写入本地文件系统。
- 密钥管理服务的访问权限必须遵循最小权限原则，按服务/环境隔离。
- 密钥的创建、读取、更新、删除操作必须记录完整的审计日志。
- 开发和测试环境使用独立的密钥实例，禁止与生产环境共享密钥。

## 3. 轮换策略

- 所有密钥和凭据必须定义轮换周期，生产环境密钥轮换周期不超过 90 天。
- 密钥轮换必须支持零停机，采用双密钥并行过渡策略。
- 发现或怀疑密钥泄露时，必须在 1 小时内完成紧急轮换。
- 轮换操作应尽可能自动化，减少人工介入带来的操作风险。
- 轮换完成后必须验证所有依赖服务正常运行。

## 4. CI/CD 密钥注入

- CI/CD 流水线中的密钥必须通过平台原生的 Secret Store 注入（如 GitHub Secrets、GitLab CI Variables）。
- 禁止在流水线配置文件（如 `.github/workflows/*.yml`）中明文写入密钥。
- 构建产物（镜像、包、制品）中禁止包含密钥，构建阶段使用的密钥必须在构建后清除。
- 流水线日志必须自动遮蔽已注册的密钥值，防止意外泄露。
- 部署脚本从密钥管理服务动态拉取配置，禁止通过环境变量传递长期有效的密钥。

## 5. 证书管理

- TLS 证书必须配置自动续期机制（如 Let's Encrypt + certbot 或云平台托管证书）。
- 证书到期前 30 天触发告警，到期前 7 天升级为紧急告警。
- 内部服务间 mTLS 证书由统一的内部 CA 签发，证书有效期不超过 1 年。
- 禁止使用自签名证书用于生产环境的外部通信。
- 证书私钥的存储和访问权限必须严格限制，与密钥管理服务集成。

## 6. Git 预防措施

- 仓库必须配置 `.gitignore` 排除所有可能包含密钥的文件（.env、*.pem、*.key 等）。
- 推荐启用 pre-commit hook 集成 git-secrets 或 detect-secrets 工具，阻止密钥提交。
- CI 流水线应包含密钥扫描步骤（如 truffleHog、gitleaks），发现泄露立即阻断。
- 历史提交中发现的密钥必须立即轮换，并评估是否需要清理 Git 历史。
- 仓库应定期执行全量密钥扫描，覆盖所有分支和标签。

## 7. 验证重点

- 源码和配置文件中是否存在硬编码的密钥或凭据
- 生产环境密钥是否由密钥管理服务托管
- 密钥轮换策略是否已定义并自动化执行
- CI/CD 流水线是否通过 Secret Store 注入密钥
- Git 仓库是否配置了密钥泄露预防机制
