# Soft WAF 平台适配与测试前置约束

适用于以 `nginx`、`apache` 为主要防护对象、运行在 Linux 多发行版上的软 WAF 项目。

## 1. 适用范围

- `ylwaf/nginx/`
- `ylwaf/apache2/`
- Linux 发行版适配、安装、编译、打包与部署脚本
- 与软 WAF 启动、装载、联调、回归测试相关的前置动作

## 2. 平台适配原则

- 发行版差异应显式建模，至少区分发行版家族、版本、包管理器、库路径、服务管理方式和默认配置目录。
- `nginx` 与 `apache` 的适配差异必须收敛到明确边界，不允许把平台判断散落在规则语义与核心处理逻辑中。
- 安装、编译、装载、卸载、升级、回滚应形成完整链路，而不是只验证其中一个阶段。
- 适配逻辑优先表达为可复用脚本、模板或矩阵，而不是一次性人工步骤。

## 3. 发行版适配要求

- 变更设计时必须说明目标发行版范围，例如 `CentOS/RHEL`、`Rocky/AlmaLinux`、`Ubuntu/Debian`。
- 客户现网中的低版本 `nginx` / `apache` 环境应默认优先纳入适配评估；若要声明不支持，必须给出明确证据、风险说明和替代路径。
- 必须说明目标 `nginx`、`apache/httpd` 主版本与模块装载方式。
- 必须明确编译依赖、运行依赖、系统库差异、动态库路径和工具链前提。
- 必须明确配置文件路径、模块目录、日志目录、PID 目录、systemd/unit 文件差异。
- 若仅覆盖某个发行版子集，必须显式标注未覆盖范围和降级验证原因。

## 4. 安装与编译约束

- 任何涉及安装和编译的改动，都必须同时说明源码编译路径与可交付安装路径是否都受影响。
- 构建参数、编译选项、依赖探测、安装前检查和失败回退步骤必须可追踪。
- 不允许把发行版相关路径、编译参数或模块目录静默写死在多个脚本中。
- 涉及 `nginx` 或 `apache` 模块编译、装载方式变化时，必须说明对现有部署方式的兼容性影响。

## 5. 自动化测试前置动作

每次启动集成测试、回归测试或安装验证前，至少确认以下前置动作：

- 测试机发行版、内核、包版本和 Web Server 版本已记录。
- `nginx` 或 `apache` 进程状态已清理，旧 PID、旧 socket、旧临时目录和残留模块已处理。
- 测试配置、模块文件、规则文件、证书和日志目录已部署到预期位置。
- 端口占用、权限、SELinux/AppArmor、防火墙与 systemd 状态已检查。
- 测试所需依赖、动态库、环境变量和探针工具已就绪。
- 历史审计日志、缓存、上次测试产物和临时工作目录已清理或归档。
- 启动前健康检查命令、版本检查命令和配置校验命令已可执行。

## 6. 启动与验证要求

- 启动验证至少覆盖配置检查、模块装载成功、关键规则生效和日志路径可用。
- 若测试依赖服务重启，必须说明重启方式、观察窗口和失败回滚步骤。
- 自动化测试应区分 smoke、适配验证、规则回归、安装回归，不应混成一个不可解释的大脚本。
- 测试失败时，至少保留发行版信息、服务状态、模块装载信息、关键日志和执行命令。

## 7. 交付证据

涉及平台适配、安装编译或测试前置动作的变更，交付时至少给出：

- 影响的发行版与 Web Server 组合
- 影响的安装、编译、部署或启动路径
- 已执行的前置动作与验证项
- 未覆盖矩阵与降级说明
- 回滚方式或环境恢复方式
