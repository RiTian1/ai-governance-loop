# 对比矩阵

| 维度 | 有 Governance | 无 Governance |
|---|---|---|
| 需求识别 | 先判断是否属于规则语义变化 | 容易当成普通接口容错修复 |
| Agent 起手动作 | 先读 `project-governance.yaml` 和治理索引 | 直接搜索代码并实现 |
| 变更分析 | 会列出受影响场景组与验证层级 | 往往只盯当前接口或单个 case |
| E2E 策略 | 修订场景族与回归门禁 | 可能只补单点用例 |
| 证据输出 | 有测试计划、影响分析、降级说明 | 常只有实现说明或简单测试结果 |
| 可复用性 | 新规则会沉淀到治理基线 | 规则容易只存在于一次对话里 |
| CI 接入潜力 | 容易落成代码变更到场景组映射 | 很难形成稳定门禁 |
